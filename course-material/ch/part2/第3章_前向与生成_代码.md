# 第 3 章 前向与生成（代码实现）

给模型一串 token IDs，它怎样算出下一个 token，又怎样连续生成？本章把[概念篇](./第3章_前向与生成.md)中的流程写成一个可以在 CPU 上运行的 Qwen3 小模型：embedding → Transformer Block → logits → 新 token。

我们使用随机权重，只实现 dense Qwen3 的全量因果注意力。每步重算完整前缀，便于看清前向和生成的关系；KV Cache 的增量计算留给[第 4 章](./第4章_KVCache优化.md)。本章代码独立运行，无须下载模型。

## 1 本章学习目标

1. 沿着张量形状读懂 Attention、MLP 和残差连接。
2. 从最后一行 logits 生成 token，处理 EOS 和长度上限。
3. 用同权重参考实现检查前向结果，而不只看输出形状。

## 3 一次前向怎样得到 logits

### 3.1 先认清形状

设 batch 大小为 `B`，序列长为 `T`，隐藏维度为 `C`，Query 头数为 `Hq`，KV 头数为 `Hkv`，每头维度为 `D`。

| 计算 | 输出形状 | 默认单请求示例 |
| --- | --- | --- |
| token IDs | `[B,T]` | `[1,3]` |
| embedding | `[B,T,C]` | `[1,3,32]` |
| Q 投影、拆头 | `[B,Hq,T,D]` | `[1,4,3,8]` |
| K/V 投影、拆头 | `[B,Hkv,T,D]` | `[1,2,3,8]` |
| 注意力分数 | `[B,Hq,T,T]` | `[1,4,3,3]` |
| 合头、输出投影 | `[B,T,C]` | `[1,3,32]` |
| 最终归一化、LM Head | `[B,T,V]` | `[1,3,64]` |

`head_dim` 单独配置，不能假设所有 Qwen3 配置都满足 `C = Hq * D`。本例的输出投影负责把各个头拼接后的向量映射回 `C`。

### 3.2 Attention 的四个动作

先用三个线性层得到 Q、K、V，再把每个 token 的向量拆成多个头。Qwen3 对 Q、K 的每个头做 RMSNorm，然后用 RoPE 引入位置信息。RMSNorm 沿最后一维归一化；RoPE 将该维度分成左右两半旋转，V 不做旋转。

GQA 让多个 Q 头共享较少的 KV 头。本例用 `repeat_interleave` 将 K/V 的头数扩展到 `Hq`，这样就能直接做矩阵乘法。它便于阅读，实际引擎可让内核直接访问共享的 KV。

注意力核心只有三步：

```python
scores = q @ k.transpose(-1, -2) / math.sqrt(self.head_dim)
scores = scores.masked_fill(~allowed, float("-inf"))
weights = scores.float().softmax(-1).to(x.dtype)
```

`allowed` 是下三角布尔矩阵：第 `i` 行只能看第 `0..i` 个输入。未来位置填入负无穷后，softmax 权重为零。最后计算 `weights @ v`，合并各个头，再经过输出投影。

### 3.3 Block 和 LM Head

每个 Block 先进行 Attention，再进行门控 MLP，两部分都在计算前归一化，并保留残差：

```python
x = x + self.self_attn(self.input_layernorm(x))
return x + self.mlp(self.post_attention_layernorm(x))
```

MLP 的计算为 `down_proj(silu(gate_proj(x)) * up_proj(x))`。它逐位置变换特征；不同 token 之间的信息交换发生在 Attention 中。

经过多个 Block 后，最终 RMSNorm 和 LM Head 将隐藏状态变成 `[B,T,V]` 的 logits。这里没有调用 Transformers 的模型前向；它只在测试里充当参照。

## 4 把一次前向变成生成循环

### 4.1 为什么只读最后一行

输入 `[1,2,3]` 时，最后一行 logits 给出“读完 3 后，下一个 token 的分数”。采样出 token 后，把它追加到输入，重复这个过程：

```python
logits = model(tokens)[0, -1]
token = int(logits.argmax())
tokens = torch.cat((tokens, tokens.new_tensor([[token]])), dim=1)
```

完整 `generate` 还会把 token 加入 `output`，随后检查 EOS。返回值只包含新增 token，EOS 本身计入结果。`max_new_tokens=0` 返回空列表，不执行模型前向。

### 4.2 贪心和温度采样

`temperature=0` 选择分数最高的 token；温度大于零时，先算 `softmax(logits / temperature)`，再按概率抽样。可以在仓库根目录启动 Python，试着运行：

```python
from examples.part2.chapter03.forward import Qwen3, generate

model = Qwen3().eval()
print(generate(model, [1, 2, 3], max_new_tokens=5, temperature=0.8))
```

Top-k、Top-p 的含义见概念篇，本例先保留这两种最小生成路径。`eval()` 设定推理模式，`inference_mode()` 关闭梯度记录；二者用途不同。

### 4.3 此时还在重复计算什么

生成第一个 token 时输入长 3，第二步长 4，第三步长 5。历史 token 的 Q/K/V 和 Block 都被重新计算。这个清楚但低效的版本可以作为下一章 KV Cache 的正确性基线。

## 5 检查结果，再对照源码

```bash
python -m pytest examples/part2/chapter03 -q
```

测试把 Transformers `4.57.1` 的随机 Qwen3 权重原样装入手写模型，在 CPU FP32 下比较 logits（`atol=2e-6, rtol=2e-5`），再比较 8 步贪心生成。另一项测试只改后两个输入 token，确认前两个位置的 logits 不变，用来检查因果掩码。

还会验证权重共享、EOS、零输出和长度上限。测试通过说明这里支持的模型配置和路径与参照一致；本例未加载真实预训练权重，也未实现 padding、滑窗、RoPE scaling 或 KV Cache。

## 6 总结与测试题

### 6.1 课程总结

前向将一串 token IDs 变成各位置的 logits；生成循环反复读取最后一行、选择新 token、追加到前缀。理解这条主线后，再用同权重对齐和因果性测试确认 Attention 的细节。

### 6.2 测试题

1. 若输入形状是 `[2,5]`、词表大小是 64，logits 的形状是什么？哪一行用来继续生成？
2. 去掉因果掩码后，哪一项测试应当失败？为什么？
3. 把 `num_key_value_heads` 从 2 改为 1，哪些张量形状变化，哪些不变？
4. 当前生成循环重复计算了哪些内容？KV Cache 可以省去其中哪些计算？
